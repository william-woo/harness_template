# ADR-020: AIF 판정 오버레이 — RLAIF/CAI 규율을 judge 에 이식

> Feature: F028 — claude.aif / localllm.aif 변형 신설
> 상태: `Accepted` (구현 — 변형 2개 + AIF 오버레이, A/B 실측 진행)
> 관련: ADR-014(Loop 2 검증 루프), ADR-018(결정론 supervisor), ADR-019(autoresearch),
> 측정 09(판정 분산이 정책 차이보다 크다)

## 맥락

측정 09 의 결론은 **판정 분산이 개선 신호를 덮는다**였다. 같은 취지의 정책이 4/4 와 1/4 로
갈렸고, 재현 실험에서 챔피언과 빈 정책이 3/6 대 3/6 동률이었다. 원인을 정책 쪽에서 찾았지만,
분산의 상당 부분은 **판정 자체**에서 나온다.

RLAIF/CAI 문헌이 같은 문제를 먼저 겪고 처방을 남겼다:

| 문헌 | 발견 | 처방 |
|---|---|---|
| Rubrics-as-Rewards | Likert 단일 점수 judge 는 분산이 크다 | **구조화 채점표** — HealthBench +31%, 작은 judge 에서 정렬 개선·분산 감소 |
| CAI (2212.08073) | CoT judge 확률이 0/1 로 붕괴 | soft label + **40–60% 클램프** (확신을 액면대로 쓰지 않음) |
| CAI | 단일 원칙 판정은 불안정 | **16원칙 앙상블** |
| RLAIF (2309.00267) | position bias 큰 모델 18% / 작은 모델 **56%** | 순서 교대 후 평균 |
| RLAIF | few-shot 예시가 라벨러 정렬을 **단조 감소** | 컨텍스트를 늘리지 않는다 |

우리 judge 는 로컬 32B — 문헌 기준으로 "작은 judge"에 해당하고, 그쪽이 처방의 효과가 가장 크다.

## 결정

### 결정 1 — 전체 적용이 아니라 전용 변형 2개에 격리한다

`claude.loope` → **`claude.aif`**, `localllm` → **`localllm.aif`** 로 복사해 그 위에만 얹는다.
14 변형 전체에 적용하면 **개선 여부를 부모와 비교할 수 없다**. 부모를 그대로 남겨두는 것이
A/B 의 전제다. LINT-MR-14 가 격리를 강제한다.

계보상 `claude.aif` 는 loope 의 자식이므로 **main ≡ claude.loope 불변식(ADR-015)은 유지**된다 —
AIF 오버레이는 main 에 들어가지 않는다.

### 결정 2 — judge 에게 "종합 판단"이 아니라 "항목별 판정 + 증거"를 요구한다

`.claude/rubrics/<name>.items.md` 가 항목형 채점표다. 각 항목은 `id | severity | 제목` +
`요구` + `증거`로 이뤄지고, judge 는 항목마다 한 줄로 `met|unmet|na` + 증거를 반환한다.

산문형 rubric(`code-review.md`)은 **삭제하지 않는다**. 사람이 읽는 기준은 산문형이고, 기계가
검증하는 채점표는 항목형이다 — 둘은 공존한다.

### 결정 3 — 증거 없는 `met` 은 판정으로 인정하지 않는다

`met` 은 `파일:행` 또는 실제 코드·출력의 인용을 증거로 요구한다(12자 이상). 없으면 그 항목을
무효화해 `UNCERTAIN` 으로 남긴다. rubric 의 `증거:` 문구를 그대로 되풀이한 것도 무효다
(측정 08 에서 확립한 에코 노트 무효화의 항목 단위 확장).

항목 누락·중복·미정의 id 는 **판정 전체를 무효**로 만든다 — 부분 판정을 추측으로 메우면
판정 기록이 신뢰를 잃는다.

### 결정 4 — 갈린 표를 한쪽으로 강제하지 않는다 (UNCERTAIN)

N회 판정을 항목별 다수결로 앙상블하고, 유효표가 과반 미달이거나 동수면 그 항목은 `UNCERTAIN`
이다. MUST 에 `UNCERTAIN` 이 하나라도 있으면 전체 판정은 `uncertain` → 에스컬레이션이다.

`verify_loop` 는 `pass|revision|fail` 만 받으므로, `uncertain` 을 그중 하나로 기록하지 않는다.
불확실성을 기록에서 지우는 것이 곧 거짓 판정의 출발점이기 때문이다. CAI 의 클램프와 같은 취지다.

### 결정 5 — 판정은 모델이, 집계는 결정론이

`aif_judge.py` 는 **모델을 호출하지 않는다**(`auto` 모드 예외). 프롬프트를 만들고, 돌아온 판정을
검증하고, 집계한다. `verify_loop` 와 같은 역할 분담이며 ADR-018 의 "supervisor 는 상태 기계"
원칙의 연장이다.

`localllm.aif` 에서만 `auto` 모드가 동작한다(cycle_driver 의 호스트 호출 계층 재사용). 다른
변형에서는 `plan → (호스트 judge) → record → aggregate` 로 쓴다 — codex/openclaw stub 과 같은
graceful degrade 패턴이다.

### 결정 6 — cycle_driver 통합은 판정 루프를 재구성하지 않는다

`localllm.aif` 의 cycle_driver 는 항목형 앙상블 결과를 **기존 결정론 findings 주입 채널**에
넣는다(`_aif_findings`). judge 는 여전히 자기 판정을 기록하고, 드라이버는 대신 기록하지 않는다
(측정 08 에서 확립한 "미기록 판정을 judge 실패로 검출" 불변식 유지).

즉 AIF 의 기여는 **judge 를 교체하는 것이 아니라 judge 입력의 증거 품질을 올리는 것**이다.
S06 을 통과시킨 것이 기계적 findings 주입이었으므로, 검증된 채널을 재사용한다.

기본 반복은 2회 — 두 판정이 일치할 때만 지적이 되고, 갈리면 "직접 확인하라"로 전달된다.
`CYCLE_AIF=0` 으로 끌 수 있고, 어떤 실패에도 빈 목록을 반환해 사이클을 막지 않는다.

## 원본 문헌과의 차이 (의도된 이탈)

| 항목 | 문헌 | 이 이식 | 이유 |
|---|---|---|---|
| 용도 | 보상 신호(RL 학습) | **게이트 신호**(판정) | 우리는 모델을 학습시키지 않는다. 같은 판정 품질 문제를 공유할 뿐 |
| 앙상블 축 | 원칙 16개를 샘플·앙상블 | **반복 N회**를 앙상블 | 우리 rubric 은 항목 전체를 매번 판정한다(항목이 10개뿐) |
| 확신도 처리 | soft label 40–60% 클램프 | `UNCERTAIN` 분류 | 이산 verdict 에는 확률 클램프가 정의되지 않는다 |
| position bias | 순서 교대 후 **평균** | 순서 교대 후 **불일치 검출** | 이산 판정의 평균은 의미가 없다 → 갈리면 UNCERTAIN |
| few-shot | 라벨러 정렬을 낮춘다 | 예시를 넣지 않는다 | 측정 08(긴 지시 → 도구 호출 실패)과 같은 방향 |

## 대안 검토

- **모든 변형에 적용**: 기각. 사용자 지적대로 전체 적용은 **차이를 구별할 수 없게** 만든다.
- **산문형 rubric 을 항목형으로 교체**: 기각. 사람이 읽는 기준을 기계 형식으로 바꾸면 rubric 의
  설명력이 떨어진다. 추가 게이트로 둔다.
- **judge 를 항목형 앙상블로 완전 대체**: 기각(결정 6). 판정 루프 재구성은 측정 08 이 확립한
  불변식들을 흔든다. 먼저 주입 채널로 효과를 측정하고, 이득이 확인되면 그때 검토한다.
- **통계적 유의성까지 자동 판정**: 보류. 측정 09 와 같은 이유 — 현재 표본으로는 검정력이 없다.

## 비용

항목형 판정은 역할당 N회 추가 모델 호출이다. 기본 2회 설정에서 사이클당 4회(reviewer+qa)가
늘어난다. `localllm.aif` 는 로컬 GPU 라 과금이 없지만 **사이클 시간이 늘어난다** — A/B 비교에서
AIF 구간이 더 느린 것은 예상된 차이다.

## 결과

- 변형 2개 신설, LINT-MR-14 격리 (107 PASS / 0 BLOCK)
- `aif_judge.py` 합성 판정 테스트: 증거 결함 검출·무효 판정 제외·동수 UNCERTAIN·과반 미달
  UNCERTAIN 이 모두 설계대로 동작
- A/B 실측은 측정 10 에 기록한다. `claude.aif` 는 적합도 함수(무인 스위트)가 없어 **구조 이식까지**
  이고, 수치 비교는 `localllm.aif` 에서만 가능하다 (ADR-019 결정 5 와 같은 비대칭)
