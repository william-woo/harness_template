# ADR-023: vela 버전 계보 신설 + Atlassian(Jira·Confluence) 연동

> Feature: F032 — `claude.vela.v0.1` 변형 신설 + Atlassian 오버레이
> 상태: `Accepted` (구현 — 읽기 경로·매핑 결정론 완료. 쓰기 경로는 승인 게이트 뒤)
> 관련: ADR-015(미러 SSOT), ADR-014(loop 오버레이), ADR-020(aif — 전용 변형 격리 선례),
> ADR-021(모델 축 분기)

## 맥락

두 가지가 동시에 필요해졌다.

**① 변형 이름이 기능 서술로는 한계에 왔다.** 지금까지 변형은 오버레이 이름을 이어 붙였다
(`claude.gstack.auto.design.wiki.orch`). 계보를 읽기엔 좋지만 **배포 단위로는 쓰기 어렵다** —
"우리가 지금 쓰는 하네스"를 가리키는 이름이 없고, 이름이 길어질수록 새 기능마다 폴더명이
자란다. 다운스트림에 "이 버전을 쓰세요"라고 말할 단위가 필요하다.

**② 팀이 Jira·Confluence 로 일한다.** 요구사항은 Jira 에 있고 설계 문서는 Confluence 에 있는데,
하네스 산출물(`feature_list.json`·ADR·판정)은 리포 안에만 있다. 둘 사이를 사람이 수동으로
옮기고 있다.

②에 대해 "MCP 를 만들자"는 안이 먼저 나왔으나, **실측 결과 만들 필요가 없었다**:

```
claude.ai Atlassian Rovo: https://mcp.atlassian.com/v1/mcp - ✔ Connected
사이트: obigoinc.atlassian.net
권한: read:jira-work · write:jira-work · read/write:page:confluence · search:confluence
접근: Jira 프로젝트 81개 (생성 권한 포함), Confluence 스페이스 (SD·IT·프로젝트별)
```

Atlassian **공식 MCP 커넥터**가 이미 연결돼 있고 41개 도구를 제공한다. 자체 구현은 OAuth
토큰 관리·API 버전 추적·스코프 매핑을 우리가 떠안는 것이고, 그 전부를 공식 서버가 이미 한다.

## 결정

### 결정 1 — 변형 이름에 `vela.<버전>` 계보를 도입한다

앞으로 배포 단위 변형은 **`claude.vela.v<major>.<minor>`** 로 명명한다.
첫 릴리스는 `claude.vela.v0.1` 이며 `claude.loope` 1:1 복사에서 출발한다.

| 이름 축 | 용도 | 예 |
|---|---|---|
| **기능 서술** (기존) | 계보·오버레이 구성을 드러냄 | `claude.gstack.auto.design.wiki.orch` |
| **`vela.<버전>`** (신규) | **배포 단위** — "이 버전을 쓰세요" | `claude.vela.v0.1` |
| 축 접미사 (기존 유지) | 실험 축 격리 | `.aif`(판정), `.nem`(모델), `localllm`(호스트) |

기존 이름을 **개명하지 않는다.** `claude.loope` 는 SSOT 로 남고(ADR-015), vela 는 그 위의
배포 스냅샷이다. 개명하면 ADR·측정 문서의 모든 참조가 깨진다.

> **미해결로 남기는 것**: vela 와 loope 의 관계를 장기적으로 어떻게 둘지 —
> 매 릴리스마다 loope 에서 복사할지, vela 가 SSOT 를 넘겨받을지. v0.1 에서는
> **loope 가 SSOT** 이고 vela 는 복사본이다. v0.2 착수 시 재검토한다.

### 결정 2 — 자체 MCP 서버를 만들지 않는다

공식 커넥터를 쓴다. 우리가 만들면 떠안게 되는 것과, 공식이 이미 하는 것:

| 자체 구현 부담 | 공식 MCP |
|---|---|
| OAuth 토큰 저장·갱신 | Atlassian 처리 |
| Jira API v2/v3, Confluence v1/v2 변화 추적 | 서버가 버전 관리 |
| 스코프·권한 매핑 | 서버가 강제 |
| 41개 도구 재구현 | 이미 있음 |

이는 ADR-021 에서 nemotron 파인튜닝을 보류한 논리와 같다 —
**다른 곳이 무료로 주는 것을 재발명하지 않는다.**

### 결정 3 — 우리 리포가 SSOT, Atlassian 은 발행 대상

| 방향 | 허용 | 근거 |
|---|---|---|
| Atlassian → 하네스 | **읽기만** (초안 입력) | 요구사항의 출발점은 팀 도구에 있다 |
| 하네스 → Atlassian | **발행**(publish) | 산출물의 진실은 리포에 있다 |
| Atlassian 편집 → 리포 역반영 | **금지** | 두 SSOT 는 반드시 어긋난다 |

Confluence 페이지를 사람이 고쳤다면 리포를 고치고 다시 발행한다. 역반영을 허용하면
"어느 쪽이 맞는가"를 매번 판단해야 하고, 그 판단에는 정답이 없다.

### 결정 4 — API 래퍼는 만들지 않고, **멱등성만** 코드로 둔다

이것이 이 ADR 의 핵심 설계다.

MCP 도구는 **에이전트가 직접 부른다.** Python 래퍼를 두면 도구를 한 겹 감싸기만 하고
가치가 없다. 코드가 필요한 곳은 단 하나 — **"이걸 이미 발행했는가"** 다.

모델에게 그 기억을 맡기면 중복 페이지·중복 이슈가 생긴다. 되돌리기 어렵고 팀에 알림까지 간다.
`atlassian_map.py` 가 `(kind, local_id) → (url, remote_id, digest, revision)` 매핑을 들고
종료 코드로 답한다:

| exit | 의미 | 행동 |
|---|---|---|
| 0 | digest 동일 | 발행하지 않는다 |
| 2 | 미기록 | 신규 생성 |
| 3 | digest 변경 | 기록된 URL 을 갱신 |

**판단은 모델이, 멱등성은 코드가** — ADR-014 의 grader(결정론)/judge(모델) 분리를 발행
경로에 적용한 것이다.

### 결정 5 — 발행은 PR 과 같은 승인 층위

Jira 이슈·Confluence 페이지는 **외부 공개**이고 팀에 알림이 간다. 자율 진행 대상이 아니다.
자동 발행하지 않는다 — `handoff`·`lint` 가 부르지 않고, 사용자가 요청할 때만 실행한다.

### 결정 6 — vela 계열 전용으로 격리한다 (LINT-MR-15)

Atlassian 오버레이 3파일 + 상태 디렉토리를 `claude.vela.*` 에만 둔다.
이유는 ADR-020 결정 1 과 같다 — 전체 적용하면 **연동 유무의 차이를 관찰할 수 없다.**
또한 다른 변형(특히 `localllm` 계열)은 호스트가 달라 이 커넥터 자체가 없다.

## 범위 — 3단계 중 1단계까지 구현

| 단계 | 내용 | 상태 |
|---|---|---|
| **1. 읽기** | Jira 이슈 → `feature_list.json` 초안 | ✅ 규약·커맨드 완비 |
| **2. 발행** | ADR·체크포인트 → Confluence, 판정 → Jira 코멘트 | ✅ 경로·멱등성 완비, **실사용 미검증** |
| 3. 상태 동기 | `feature status → Jira status` **단방향만** | ⏸ 미착수 |

3단계를 단방향으로 제한하는 이유: 양방향은 충돌 해결 규칙이 필요하고, 그 복잡도가
얻는 것을 넘는다. `passes` 는 QA 에이전트 단독 권한이므로 Jira 상태로 바꾸지 않는다.

## 대안 검토

| 대안 | 기각 이유 |
|---|---|
| 자체 MCP 서버 구현 | 공식 커넥터가 이미 있다 (결정 2) |
| Python API 클라이언트 (`jira`/`atlassian-python-api`) | 외부 의존성 추가 + MCP 와 기능 중복. 하네스는 stdlib only |
| 모든 변형에 적용 | 차이를 관찰할 수 없다 + 호스트가 다른 변형이 있다 (결정 6) |
| 양방향 상태 동기 | 두 SSOT 문제 — 충돌 해결에 정답이 없다 (결정 3) |
| 발행을 자동화 (handoff 훅) | 외부 공개를 자동 트리거하는 것은 위험 대비 이득이 없다 (결정 5) |
| 기존 변형을 vela 로 개명 | ADR·측정 문서의 모든 참조가 깨진다 (결정 1) |

## 비용

- 변형 하나 추가 (159 파일). 부모 `claude.loope` 변경 시 미러 대상이 하나 늘어난다
- Atlassian 커넥터는 **사용자별 인증**이다. 템플릿을 받은 다운스트림은 각자 연결해야 하고,
  미연결 시 안내만 출력하고 하네스는 정상 동작해야 한다 (graceful degrade)
- 매핑 파일(`.claude/state/atlassian/map.json`)은 **머신 로컬**이다. 다른 머신에서
  발행하면 중복이 생길 수 있다 — 팀 공유가 필요해지면 그때 커밋 대상으로 승격을 검토한다

## 결과

- `claude.vela.v0.1` 신설 (159 파일), LINT-MR **134 PASS / 0 BLOCK**
- Atlassian 커넥터 실측 확인: `obigoinc.atlassian.net`, Jira 81 프로젝트, 읽기·쓰기 권한
- `atlassian_map.py` 왕복 시험 통과 (종료 코드 0/2/3/1 정확)
- **미검증**: 실제 Confluence 페이지 발행·Jira 코멘트 (쓰기 경로는 승인 뒤에 실사용 검증)
