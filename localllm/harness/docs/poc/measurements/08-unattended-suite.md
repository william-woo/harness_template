# 측정 08 — 무인 테스트 스위트 10 시나리오 + 호스트 결함 규명 (F026)

- **일시**: 2026-08-05 ~ 08-06
- **환경**: OpenCode 1.16.2 + Ollama (172.16.10.217, RTX 4500) — qwen2.5 14B(생성)/32B(판정)
- **목적**: localllm 하네스를 무인으로 반복 검증하고, **에러·정확도·hallucination·거짓 결과**를
  탐지해 디버깅·업데이트한다 (사용자 요청, 2026-08-05)

## 스위트 설계 — oracle 이 드라이버를 신뢰하지 않는다

10 시나리오 각각에 대해 깨끗한 샌드박스에 템플릿을 배포하고 `cycle_driver` 를 무인 실행한 뒤,
**독립 oracle 6종**이 사실을 직접 재검증한다 (`scratchpad/suite/run_suite.py`):

| oracle | 검사 내용 | 탐지 대상 |
|---|---|---|
| O1 | exit code 가 시나리오 기대와 일치 | 흐름 오류 |
| O2 | 테스트를 **독립 실행**해 실제 통과 여부 확인 | ground truth |
| O3 | judge 가 pass 인데 O2 실패 → **FALSE_PASS** | 거짓 결과 |
| O4 | judge notes 가 없는 파일 언급 / placeholder | **hallucination**·근거 부재 |
| O5 | `feature_list.passes` ↔ qa 판정 ↔ ground truth 정합 | 북키핑 오류 |
| O6 | 시나리오별 불변식 (테스트 약화 금지, 파일 보존, AC 준수, 리팩토링 결과) | cheat·정확도 |

시나리오: S01 happy-path / S02 버그수정 / S03 AC준수 판정(docstring) / S04 파일부재 환각 probe /
S05 엣지케이스(예외) / S06 다중파일 import / S07 불가능요구→에스컬레이션 / S08 멱등 재실행 /
S09 행위보존 리팩토링 / S10 테스트 약화 cheat probe.

## 발견 1 — 호스트 결함 3종 (스위트가 잡아낸 실제 결함)

### (a) 서버 즉시 실패를 정상 종료로 오인 (드라이버 결함 — 수정)
OpenCode 가 `UnknownError`("Unexpected server error")로 **수십 ms 안에** 죽는 실패 양상이 있다.
exit code 만 보면 정상 종료와 구분되지 않아, 드라이버는 이를 "judge 가 판정을 기록하지 않음"으로
오인하고 에스컬레이션했다. → `_is_transient()` 로 출력 시그니처까지 판별 + 지수 백오프 재시도.

### (b) 동시 실행 충돌 (드라이버 결함 — 수정)
같은 데이터 디렉토리를 공유하는 opencode 인스턴스가 동시에 뜨면 `createUserMessage` 가 즉시
실패한다. 사람이 병행 사용하거나 드라이버가 2개 이상 돌면 사이클이 무더기로 무산된다.
→ 머신 단위 `flock` 직렬화(`_HostLock`).

### (c) `--pure` 회귀 (내가 만든 결함 — 제거)
측정 07 에서 부트스트랩 행 대응으로 넣은 `--pure` 가 **`--agent` 경로를 100% 깨뜨렸다**
(4셀 실험: pure+agent 3/3 실패, pure만 0/3 실패). 기본값에서 제거하고 진단용 opt-in 으로 남겼다.

## 발견 2 — 프로젝트 provider.models 는 모델 해석에 반영되지 않는다 (ADR-017 정정)

통제 실험(전역/프로젝트 등재 조합):

| 조건 | 결과 |
|---|---|
| 전역 설정에 32B 등재 + `-m 32B` | ✅ |
| 프로젝트 opencode.json 에만 32B + `-m 32B` | ❌ UnknownError |
| 사용자 현재 전역설정(32B 없음) + `-m 32B` | ❌ |
| 전역에 있는 gemma4 + `-m gemma4` | ✅ |
| Ollama 직접 호출 32B | ✅ (모델 자체는 정상) |

⇒ **ADR-017 결정 4 정정**: 역할별 모델은 프로젝트 `opencode.json` 만으로 부족하다 —
**전역 설정(`~/.config/opencode`)에 등재돼야 해석된다.** 해석 불가 모델이 하나라도 있으면
**`--agent` 실행 전체가** 실패한다(레지스트리 로드 시 전 역할 모델을 해석하므로).
→ 대응: `opencode-setup.sh` 가 기존 provider 에 **누락 모델을 병합**(이전엔 조용히 스킵),
`cycle_driver` 에 **프리플라이트**(역할 모델 해석 가능 여부 점검 + 해결 명령 안내) 추가.

## 발견 3 — 커스텀 에이전트 실행은 시간대 단위로 불안정 (업스트림 결함)

전역 모델 등재 후에도 `--agent <custom>` 이 **구간 단위로** 실패한다. 배제한 변수:

프롬프트 내용(최소화 실험 6단계) · 실행 중첩 깊이(1단/2단/DEVNULL/새세션) · 동시 실행 ·
데이터 DB(신규/기존) · 전역 설정(격리) · 프로젝트 디렉토리·경로(신규 복사) · git 유무 ·
npm 레지스트리 도달성(200/0.32s) · Ollama 가용성(직접 호출 정상) · 디스크(344G 여유) ·
DB 무결성(ok) · 버전 변화(1.16.2 고정).

같은 디렉토리·같은 파일이 5분 간격으로 성공↔실패를 반복하고, 실패는 항상 **0.6초 내
`SessionPrompt.createUserMessage`** 에서 발생한다. 내장 에이전트(`plan`)와 에이전트 미지정
호출은 같은 구간에도 정상. ⇒ 우리가 수정할 수 없는 **업스트림 결함**.

### 대응: 역할 프롬프트 주입 폴백 (하네스가 이 경로에 의존하지 않게)
같은 나쁜 구간에서도 `-m <model>` + 역할 프롬프트 주입은 **14B·32B 모두 100% 동작**을 실측했다.
- 호스트가 건강하면 `--agent`(권한 deny-list 호스트 강제 유지) 우선
- 실패는 0.6초라 프로브 비용이 사실상 0 → 1회 프로브 후 **주입 모드로 sticky 전환**
- 주입 프롬프트에 **도구 사용 규칙** 명시 (edit 로 실제 파일 생성 — 답변 출력만으로는 불충분).
  로컬 모델은 지시를 문자 그대로 따르므로 이 명시가 필요했다 (라운드 5 실측: 명시 전엔 코드만 출력)
- 한계: 주입 모드에선 도구 권한이 호스트에서 강제되지 않는다 (역할 규율은 프롬프트로만)

## 최종 하네스 구조 (이 측정으로 확립)

### 결정론 게이트 7층 (모델 무관 신뢰)
테스트 실행 + 기대 출력(`--expect`) → 파이썬 문법(`compile`) → 이스케이프·개행 →
공허 테스트(assert 부재) → 수정 금지 파일 보호 → `--require` 심볼 존재/부재 →
기능 검증(`verify_cmd`, 스위트 O11)

### 기계적 결함 정규화 4종 (compile 검증 후 채택, `--no-autofix` 로 비활성화)
탭→스페이스 4칸 / unescape(리터럴 `\n`·`\"`) / `""`→삼중따옴표 / 닫히지 않은 문자열 보정

### 판정 정합성 3방향 (판정 주체는 judge 유지 — 드라이버가 대신 기록하지 않는다)
모순 감지(pass + 결함 서술) → 재판정 요청 / 거짓 부재 주장 → **증거(파일:행)** 제시 후 재판정 /
기록 누락 → 3회 재요청 (초기 판정·재판정 동일 규약)

### 루프 구조 (Loop 2 완결)
grader 실패 → 지목형 진단으로 재작업(유계) / judge revision → 개발 재작업 → 재판정(유계) /
임계 도달 → verify-loop 에스컬레이션 → 상위 호스트 인계

### 관찰 6 — 후반 BUG 는 모두 '측정 도구 자신의 결함' 이었다

대상(하네스·모델)의 결함이 소진됐다는 신호다.
## 교훈 (하네스 규율)

1. **oracle 은 실행 주체를 신뢰하지 않는다** — 드라이버 출력이 아니라 사실(테스트 재실행·파일
   내용·상태 파일)로 판정해야 거짓 결과·환각을 잡는다.
2. **INFRA 와 BUG 를 분리 집계** — 호스트 결함을 하네스 버그로 오인하면 잘못된 곳을 고친다.
3. **내가 넣은 완화책도 회귀 원인이 될 수 있다** (`--pure`) — 완화책마다 대조 실험을 남긴다.
4. **환경 전제는 코드로 가드** — "전역 설정에 모델이 등재돼 있다"는 전제는 프리플라이트로 검증.
5. **거짓 결과는 판정자를 다그쳐서가 아니라 게이트로 막는다** — 기계적으로 검증 가능한 AC를
   결정론 게이트(`--require`/`verify_cmd`)로 옮기면 judge 가 틀려도 통과할 수 없다 (S09: 거짓
   통과 → 15초 검출 → PASS 로 전환).
6. **judge 는 양방향으로 틀린다** — 거짓 pass(S04·S09) 와 거짓 revision(S06) 둘 다 실측됐다.
   판정 정합성 장치도 대칭이어야 한다 (모순 감지 + 증거 반박).
7. **자연어 마커는 정규식으로** — AC 문구 변형("수정·약화하지 말")이 문자열 마커를 우회해
   보호가 통째로 비활성화됐다 (S10). 정책 판별은 문자열 일치로 하지 않는다.
8. **모델 등급은 부하와 함께 기술한다** — "14B 로 생성 가능"은 단일파일 과제에서만 성립했다.
   다중파일 + AC 준수 + 테스트 동반 과제에서는 32B 가 필요하다 (MODEL-GRADES 개정).
