# 측정 09 — autoresearch 자가 실험 루프 (F027 / ADR-019)

> 대상: `localllm` 변형 · OpenCode 1.16.2 + Ollama(원격 RTX 4500) · `qwen2.5:32b-instruct-q4_K_M`
> 적합도 함수: 무인 스위트(F026) 시나리오 **S06**(다중 파일 + import 체인) · **S09**(행위 보존 리팩토링)
> — 측정 08 안정 구간에서 재현율이 가장 낮았던 두 시나리오다 (S06 47%, S09 67%).

## 무엇을 측정했나

karpathy/autoresearch 를 이식한 루프가 ① 설계대로 동작하는지 ② 실제로 정책을 개선하는지.
실험 1건 = 베이스라인 측정 → 후보 제안(로컬 LLM) → 후보 측정 → 무결성 검사 → KEEP/DISCARD.

## 실험 2건 (S06,S09 × 2반복 = 구간당 4회)

| 실험 | 베이스라인 | 후보 | 판정 | 소요 |
|---|---|---|---|---|
| exp-001 | 빈 정책 **0/4** | developer 정책 A **2/4** | ✅ KEEP | 19분 |
| exp-002 | 정책 A **4/4** | developer 정책 B **1/4** | ↩︎ DISCARD | 44분 |

세부 실행 (verdict / exit / 초):

```
exp-001 base(빈 정책) : S06 MODEL(2,296) S09 MODEL(2,94)  S06 MODEL(2,99)  S09 MODEL(2,59)
exp-001 cand(정책 A)  : S06 PASS (0,279) S09 MODEL(2,59)  S06 PASS (0,166) S09 MODEL(2,60)
exp-002 base(정책 A)  : S06 PASS (0,187) S09 PASS (2,187) S06 PASS (0,161) S09 PASS (0,366)
exp-002 cand(정책 B)  : S06 MODEL(2,100) S09 PASS (0,171) S06 MODEL(2,129) S09 BUG (2,208)
```

두 후보 정책의 문구는 사실상 같은 말이다:

```
정책 A (KEEP)                                  정책 B (DISCARD)
- 필요한 상수 정의를 각 파일에 포함하라          - import 한 모듈이 올바로 참조되는지 검토하라
- 참조된 모듈·import 를 실제로 만들고 연결하라   - 과제에 필요한 상수를 명시적으로 정의하라
- 누락된 식별자·내용이 없는지 확인하라           - 따옴표·들여쓰기·개행 일관성을 줄마다 확인하라
- 개행/따옴표/들여쓰기를 일관되게 유지하라       - 과제가 요구한 식별자·내용이 빠지지 않게 하라
- 검증 우회·테스트 약화 금지                    - 검증 단계 우회·테스트 약화 금지
```

**같은 취지의 정책이 4/4 와 1/4 로 갈렸다.** 이 시점에서 "정책 A 가 우수하다" 는 결론은
근거가 약하다 — 측정값이 정책 차이가 아니라 실행 간 분산을 보고 있을 가능성이 크다.

## 재현 실험 — 정책 A vs 빈 정책, 3라운드 교차

같은 배치에서 두 정책을 번갈아 3회씩 (S06,S09 × 3 = 각 6회):

| 구간 | PASS | 실행 순서 |
|---|:-:|---|
| 정책 A (챔피언) | **3/6** | S06 MODEL · S09 PASS / S06 MODEL · S09 PASS / S06 MODEL · S09 PASS |
| 빈 정책 | **3/6** | S06 PASS · S09 PASS / S06 MODEL · S09 MODEL / S06 MODEL · S09 PASS |

**동률이다.** exp-001 이 KEEP 으로 기록한 개선(0/4 → 2/4)은 통제된 재현에서 사라졌다.

전 배치를 합치면 정책 A 9/14(64%) vs 빈 정책 3/10(30%) 이지만, 이 비교는 **배치가 다르다**.
같은 정책 A 가 배치마다 2/4 → 4/4 → 3/6 (50~100%) 로 흔들렸으므로, 배치 간 격차는 관측된
분산 범위 안에 있다. 합산 비교의 Fisher 단측 검정도 p = 0.107 로 유의하지 않다.

## 결론

### 1. 루프는 설계대로 동작한다
KEEP · DISCARD 가 모두 실측에서 발생했고, 불변 매니페스트 검사·paired 베이스라인·정책 주입이
모두 정상 작동했다. `promote` 는 근거(베이스라인·후보·delta·거짓 결과 수)를 출력하고 `--yes`
없이는 아무것도 쓰지 않는다.

### 2. 첫 실측의 결론은 "승자 정책" 이 아니라 "표본이 노이즈에 지배된다"
S06·S09 구간의 실행 간 분산이 정책 간 차이보다 크다. **구간당 4~6회로는 어떤 정책도 채택할
근거가 되지 않는다.** 유의미한 판정을 하려면 반복을 크게 늘리거나(구간당 20회 이상),
분산이 작은 시나리오를 적합도 함수로 골라야 한다.

### 3. 사람 승인 게이트의 가치가 첫 실험에서 실증됐다
exp-001 은 자동 채택 설계였다면 그대로 하네스에 반영됐을 KEEP 이다. 재현 실험은 그 개선이
**존재하지 않음**을 보였다. autoresearch 의 "결과는 shipped improvement 가 아니라 starting
hypothesis" 가 우리 환경에서도 그대로 맞다 — 이 측정 시점에 승격된 정책은 **없다**.

### 4. 측정기 결함은 실험을 무효로 처리해야 한다 (이 측정에서 반영)
exp-002 후보 구간에 BUG 1건이 있었다. BUG 는 하네스·oracle 자체 결함이므로 그 구간의 점수는
신뢰할 수 없는데, 최초 구현은 ACCURACY 만 실격 사유로 봤다. 이 측정 뒤 **어느 구간이든 BUG 가
있으면 실험을 INVALID 로 기록**하도록 고쳤다.

## 운영 지침 (다운스트림)

- 실험 1건 = 스위트 2회 실행이다. 시나리오 2개 × 2반복이면 **약 20~45분**, GPU 를 계속 점유한다.
- 유휴 시간(밤새) 에 `--experiments N --budget-min M` 으로 돌리고, 아침에 `status` 로 원장을 본다.
- **KEEP 을 곧바로 승격하지 않는다.** 같은 정책으로 재현 실험을 한 번 더 돌린 뒤 판단한다.
- 실험 방향은 코드가 아니라 `program.md` 의 "관찰된 약점" 을 고쳐서 조종한다.

## 미해결 / 다음

- **반복 예산 대 정확도**: 구간당 몇 회부터 정책 차이가 분산을 넘는지 미측정. S06/S09 는 분산이
  커서 적합도 함수로 비싸다 — 게이트 지배 시나리오(S02/S03/S07/S10) 는 분산이 0 에 가깝지만
  개선 여지도 없다. **중간 분산 시나리오의 탐색**이 다음 과제다.
- **정책 다양성**: 두 후보 모두 developer 를 골랐고 문구도 비슷했다. 제안 프롬프트가 역할·전략을
  더 넓게 탐색하도록 유도할 여지가 있다 (원본에서 program.md 가 하는 역할).
