# Items — code-review (AIF 항목형)

<!-- aif-items: v1 -->

> 산문형 [code-review.md](code-review.md) 의 항목형 판본. 형식은 [_items-schema.md](_items-schema.md).
> Reviewer 가 항목별로 판정하고 `aif_judge.py` 가 증거를 검증·앙상블한다.

### M1 | MUST | docstring
요구: 새로 추가·변경된 공개 함수/클래스에 docstring 이 있다.
증거: 각 docstring 의 첫 줄을 `파일:행` 과 함께 인용
판정: 대상이 하나라도 누락되면 unmet

### M2 | MUST | 단위 테스트
요구: 새 기능·변경에 테스트가 동반되고 실행 시 통과한다.
증거: 테스트 함수명과 `파일:행`, 그리고 실행 결과 줄
판정: 테스트가 없거나 assert 가 없으면 unmet

### M3 | MUST | 경계 에러 처리
요구: 외부 I/O·API·사용자 입력 경계에서 방어하고, 예외를 삼키지 않는다.
증거: 방어 코드의 `파일:행`
판정: 경계가 없는 순수 로직 변경이면 na

### M4 | MUST | 보안
요구: 자격증명 하드코딩이 없고 입력 검증이 있다.
증거: 검증 코드의 `파일:행`, 또는 자격증명 부재를 확인한 검색 결과
판정: 의심 문자열이 있으면 unmet
증거유형: 부재

### M5 | MUST | Surgical Changes
요구: 과제와 무관한 대량 변경·리포맷이 섞이지 않았다.
증거: 변경 파일 목록과 각 파일의 변경 성격 한 줄
판정: 무관한 변경이 있으면 unmet
증거유형: 부재

### M6 | MUST | 계약 준수
요구: 변형별 외부 의존성 정책(zero-dep 등)을 위반하지 않는다.
증거: import 문의 `파일:행` 또는 신규 의존성 없음을 확인한 근거
판정: 허용 카탈로그 밖 의존성이 있으면 unmet
증거유형: 부재

### S1 | SHOULD | 네이밍
요구: 의도가 드러나는 이름을 쓴다 (Boolean 은 is/has/can).
증거: 대표 식별자 2개의 `파일:행`

### S2 | SHOULD | 함수 크기·단일 책임
요구: 함수가 40줄 이하이고 한 가지 일을 한다.
증거: 가장 긴 함수의 `파일:행` 과 줄 수

### S3 | SHOULD | 중복
요구: 3회 이상 반복되는 코드가 없다 (단, 추측 추상화도 금지).
증거: 반복 위치들의 `파일:행`, 또는 반복 없음의 근거
증거유형: 부재

### S4 | SHOULD | 주석
요구: 주석이 why 를 설명한다 (what 나열 아님).
증거: 대표 주석 1개의 `파일:행`
