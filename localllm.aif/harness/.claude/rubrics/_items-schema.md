# AIF 항목형 rubric 스키마 (v1)

> AIF 오버레이(ADR-020)의 판정 입력 형식. 산문형 rubric(`code-review.md`)이 judge 에게
> "종합 판단"을 요구하는 것과 달리, 항목형은 **항목별 이진 판정 + 증거**를 요구한다.
> 근거: Rubrics-as-Rewards — 구조화된 채점표가 **약한 judge 의 정렬을 개선하고 분산을 줄인다**.

## 파일 형식

`\<name\>.items.md` 에 다음 형식으로 쓴다. 파서는 `###` 로 시작하는 줄만 항목으로 인식한다.

```
<!-- aif-items: v1 -->

### M1 | MUST | docstring
요구: 새로 추가·변경된 공개 함수/클래스에 docstring 이 있다.
증거: 각 docstring 의 첫 줄을 `파일:행` 과 함께 인용
판정: 하나라도 없으면 unmet
```

- **헤더**: `### <id> | <severity> | <짧은 제목>` — id 는 영숫자, severity 는 `MUST` / `SHOULD`
- **요구**: 충족 조건 (판정 대상)
- **증거**: `met` 으로 판정하려면 반드시 제시해야 하는 것
- **판정**: 경계 사례 처리 규칙 (선택)
- **증거유형**: `위치`(기본 — `파일:행`/인용 필수) 또는 `부재`(선택)
  - `부재` 는 "자격증명 없음"처럼 **없음을 주장하는 항목**이다. 위치 증거가 원리상 불가능하므로
    대신 **확인한 범위 서술**(20자 이상)을 요구한다. 위치 증거를 강요하면 상시 UNCERTAIN 이 된다.

## judge 가 반환해야 하는 형식

항목당 한 줄. 순서는 무관하고, **모든 항목이 정확히 한 번** 나와야 한다.

```
M1: met | src/auth.py:12 | "사용자 ID로 사용자를 조회한다"
M2: unmet | 테스트 파일이 없음
M3: na | UI 변경이 없어 해당 없음
```

`<id>: <met|unmet|na> | <증거> [| <인용>]`

## 결정론 검증 (aif_judge.py 가 강제)

| 규칙 | 위반 시 |
|---|---|
| 모든 항목이 정확히 한 번 등장 | 판정 무효 (INVALID) |
| `met` 은 `파일:행` **또는** 인용 증거 필수 (12자 이상) — `증거유형: 부재` 항목은 범위 서술 20자 이상 | 해당 항목 무효 → UNCERTAIN |
| `na` 는 5자 이상 사유 필수 | 해당 항목 무효 → UNCERTAIN |
| 증거가 rubric 의 `증거:` 문구를 그대로 되풀이 | 에코 판정 → UNCERTAIN |
| 정의되지 않은 id | 판정 무효 (INVALID) |

## 앙상블과 UNCERTAIN

같은 대상을 N회 판정해 **항목별 다수결**을 취한다. 표가 갈리면 그 항목은 `UNCERTAIN` 이며,
전체 판정은 다음 순서로 결정된다:

1. MUST 중 `unmet` 이 하나라도 있으면 → **revision**
2. MUST 중 `UNCERTAIN` 이 하나라도 있으면 → **uncertain** (에스컬레이션 — 추측하지 않는다)
3. MUST 전부 `met`/`na` → **pass**

> 갈린 표를 억지로 한쪽으로 정하지 않는 것이 핵심이다. CAI 가 CoT judge 의 확률이 0/1 로
> 붕괴하자 40–60% 로 클램프한 것과 같은 취지 — **판정자의 확신을 액면 그대로 쓰지 않는다.**
